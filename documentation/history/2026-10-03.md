# 2026-10-03

## Admin API key moved to Obsidian SecretStorage

data.json travels with the vault (git, Syncthing, cloud), so the plain-text `ghostAdminKey` leaked with it.

### What was done

- `services/admin-key-secret.ts`: `readSecret`, `claimSecretName`, `bootstrapAdminKey`, `readAdminKey`. Settings keep `ghostAdminKeySecretName` (default `ghost-publish-admin-key`) + `legacySecretMigratedAt`.
- `loadSettings` runs `bootstrapAdminKey` on every device: copies the legacy key into the device's SecretStorage, keeps the plain-text copy 60 days (cross-device zero-action migration), then drops it.
- Settings row: `SecretComponent` (name only) + **Forget key**; extra **Remove plain-text copy now** row while the legacy copy exists.
- `resolveAdminKey(app, settings)` now takes `app`; `buildGhostClient` / `refreshGhostMetadata` too.
- Startup Notice + settings hint when the key is missing on this device.
- Specs: `plugin.spec.ts` (multi-device harness), `services/admin-key-secret.spec.ts`.

### Decisions

- Legacy field name kept as `ghostAdminKey` so devices still on ≤ 1.1.1 keep working during the grace period.
- First migration never overwrites a different secret with the default name (suffixes `-2`, `-3`).
- `minAppVersion` already 1.13.0 (≥ 1.11.4): unchanged.

### Open

- Needs live vault check: SecretComponent row, Forget key, Remove plain-text copy row visibility.
- A device on ≤ 1.1.1 that saves settings drops the new fields; the next new-version load re-records `legacySecretMigratedAt` (grace period restarts). Harmless.
