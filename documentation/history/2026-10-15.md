# 2026-10-15

## Unchanged notes no longer rewrite `syncedAt`

The `unchanged` short-circuit in `syncNote` still wrote a fresh `syncedAt` to the note's frontmatter. Every sync run therefore modified every already-published note, even with nothing to push: git noise in the vault, and a dirty tree that broke `git pull --rebase` mid-save.

### What was done

- `services/sync-note.ts`: the `unchanged` path returns without touching the note.
- `services/sync-note.spec.ts`: covers it (no `processFrontMatter` call on hash match).
- BR-SYNC-4, Architecture, `docs/usage.md`, `docs/configuration.md`: `syncedAt` = last sync that pushed changes.

### Decisions

- `syncedAt` now means "last push to Ghost". The Recently published view sorts on it, which matches that meaning better than "last time the sync ran".
