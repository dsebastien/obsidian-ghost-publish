# 2026-07-17

## CI — Two-phase release workflow (attestation fix)

Ported the fixed `release.yml` from obsidian-remarkable-sync (verbatim copy; old file was byte-identical to the shared original). The old workflow built and attested artifacts at the triggering commit, then created the version-bump commit and tag — so the build-provenance attestation was bound to a different commit than the release tag, and the community-catalog review rejected releases ("attestation failed cryptographic verification").

### What was done

- **`.github/workflows/release.yml`** — two-phase design: a **prepare** job (dispatch on a branch) runs the build gate (`bun run build` + `bun test`, both kept — 103 tests pass here), bumps versions, generates the changelog, commits, creates a lightweight tag, and re-dispatches the workflow at the tag ref with `publish=true`; a **publish** job (dispatch-at-tag or bare tag push) builds, attests (`continue-on-error` removed), and creates the release with `github.sha == tag commit`. Design proven live on remarkable-sync 1.5.0 (cert sha == tag commit).
- **`scripts/release.sh`** — updated the "The GitHub workflow will:" description to match the new two-phase flow.
- No repo-specific adaptation needed: `release:update-version` / `release:version-bump` / `release:changelog` scripts all exist, and `docs/release-notes.md` is generated by `scripts/generate-changelog.ts`, so the workflow's `git add` list stays as-is.
