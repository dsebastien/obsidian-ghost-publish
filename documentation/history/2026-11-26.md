# 2026-11-26

## Link back to the note and canonical_url split; post URL property

Why: a notes site can treat the Ghost post as the original of a note (the post names itself in its canonical link) while the post keeps its line that links back to the note. That site also needs the real address of each post in the note.

### What was done

- `Preset.linkBackToNoteEnabled` (new) drives the callout from `buildPostHtml`; `Preset.canonicalUrlEnabled` now drives only the `canonical_url` field.
- Migration in `sanitizePreset` (moved from `plugin.ts` to `types/preset.intf.ts`, + spec): a saved preset without `linkBackToNoteEnabled` copies `canonicalUrlEnabled`. On → both on, off → both off.
- Probe of the note URL runs when either setting needs it (BR-SYNC-6).
- Canonical field off on update: `canonical_url: null` only when the post's current `canonical_url` equals the note URL (BR-SYNC-7).
- `frontmatter.postUrl` (default `''` = off): after create / update / newsletter publish, written from the post Ghost returned, only when `status === 'published'`, the URL is not a `/p/<uuid>/` preview or `/404/`, and the value changed (BR-SYNC-8). `SyncResult.postUrl` / `postUrlNote` carry the outcome.
- `GhostApiClient.publishDraft` returns the published post (needed for its URL).
- Settings UI: two preset toggles, **Post URL** frontmatter field (placeholder `ghost_publish_url`). Docs, README, `NEXT_RELEASE.md`.

### Decisions

- Kept the saved key `canonicalUrlEnabled` for the field: a device still on 1.3.1 that reads newer data keeps setting the field when it is on (it also adds the callout, as before).
- Clearing: Ghost's Admin API schema types `canonical_url` as `["string", "null"]`; null clears it. Restricting the clear to the note URL keeps a hand-set value.
- Draft URL: Ghost's Admin output serializer replaces the URL of a non-published post with `/p/<uuid>/` (or `/email/<uuid>/`), so status is checked, not the URL alone.

### Review follow-up

- Callout text per preset: `Preset.linkBackText` (default `Canonical version:`, `DEFAULT_LINK_BACK_TEXT`), shown in the preset editor only while the link back is on (`settingEl.toggle`). Decision of the author.
- `publishDraft` returns `posts?.[0]` (`GhostPost | undefined`) and never throws after a 2xx, so `emailed` / `emailed_at` survive an odd answer. Tests: client spec with a stubbed `requestUrl`, sync spec of the dispatch failure path.
- `postUrlKeyClash`: the post URL key may not equal another managed key, a `COSMETIC_FM` key or `title`. The settings refuse it (also when another key is renamed onto it); a sync skips the write with a warning log and says so in `postUrlNote`.
- Command `resync-preset` ("Sync again every note of a preset"): preset picker (`ui/preset-suggest-modal.ts`), confirmation naming the count (`utils/resync-message.fn.ts`), then `resyncPostsForPreset` over notes with a Ghost id, `ignoreContentHash: true`, `allowEmail: false` (BR-SYNC-9). Tested with a stub client (`publish-service.spec.ts`).
- Test: no `canonical_url: null` when `notesBaseUrl` is empty.
- Second look at the command: with `ignoreContentHash` the update sends no `status`; `published` is written from the status Ghost returns (an answer without a post after an email counts as published); `date_updated` only when the hash changed; with email not allowed, a 404 on a note that waits for its email is skipped instead of recreated without the email; the picker lists enabled presets only (`plugin-resync.spec.ts`).
- Docs: update every synced device before changing the new settings (an older version drops the new keys when it saves); unchanged notes are skipped, so a cleared canonical_url waits for the next change or the new command.

- Command palette: "Sync again every note of a preset" opens the picker, then the confirmation with the right count.
